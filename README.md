# つかプロ：形を読み取ってロボットを動かす

サイト：https://tsukapro-shape-lab.bbxf5wf8wf.chatgpt.site

Chromebookのブラウザで外形を登録・認識し、Wi-Fi経由でArduino UNO R4 WiFiに命令を送ります。TB6612のA側を左、B側を右のN20モーターとして扱います。既存の配線に合わせてコードを変更してください。

## 1. Arduinoを書き込む

`RobotController/RobotController.ino`をArduino IDEで開きます。ボードマネージャーで「Arduino UNO R4 Boards」を入れ、「Arduino UNO R4 WiFi」を選択します。WiFiS3はボードパッケージに付属します。書き込みできるWindows/Mac/LinuxのArduino IDEを使う手順です。学校のChromebookだけで書き込めるかは、学校の管理設定と利用できるArduino環境によります。

先頭で変更する項目：

- `WIFI_SSID`：2.4GHzのWi-Fi名
- `WIFI_PASSWORD`：Wi-Fiのパスワード
- `ROBOT_KEY`：サイトの「接続キー」と同じ値（初期値 `tsukapro`。独自の値に変更推奨）
- `PWMA, AIN1, AIN2, PWMB, BIN1, BIN2, STBY`：実際の配線のピン番号
- `LEFT_REVERSED, RIGHT_REVERSED`：車輪の向きが逆なら該当する側を `true`

教えていただいた配線を、すでに設定済みです。

| TB6612 | Arduinoの設定 |
|---|---|
| PWMA | D2 |
| AIN1 / AIN2 | D4 / D3 |
| PWMB | D7 |
| BIN1 / BIN2 | D5 / D6 |
| STBY | 5V固定（コードでは -1） |

STBYがすでに電源のHIGHへ固定接続されている場合は `STBY = -1` にします。D2/D7は通常のanalogWriteのPWM対象ではないため、FspTimerの割り込みで250Hz・32段階のソフトウェアPWMを生成します。FspTimerはUNO R4ボードパッケージに付属します。電源回路は既存のものを使用し、このコードで電圧を変換することはできません。

書き込み後、シリアルモニタを115200 baudで開き、リセットすると `Robot IP: 192.168...` が表示されます。接続できるまでモーター出力は停止状態です。Wi-Fiが切れた後に接続が戻らない場合は、停止を確認してからArduinoをリセットしてください。

## 2. サイトと接続

1. ChromebookとArduinoを同じWi-Fiにつなぐ。
2. サイトの「ロボットをつなぐ」でIPアドレスと接続キーを入力。
3. Chromeのローカルネットワークアクセスを許可し、「接続をたしかめる」を押す。
4. 最初は車輪を浮かせ、前進1個・100〜500msで左右の方向を確認。

公開HTTPSサイトからローカルHTTP機器への通信には、対応するChromeとローカルネットワーク許可が必要です。Arduino側ではCORSとOPTIONSにも応答しますが、それだけで学校の端末管理やWi-Fiの端末間通信制限を解除できるわけではありません。接続に失敗する場合は、IP・キー・同じWi-Fiかを確認し、学校の管理者にローカル機器との通信可否を確認してください。ポート開放は不要です。サイトは公開設定で、ChatGPTへのログインは不要です。

## 3. 自作ブロックを登録

- 暗い無地の台紙に明るいブロックを1個だけ置き、真上から写真を撮る。
- 「かたちを登録」で前進・後退・左・右・停止の各欄へ写真を登録。
- 明るさの境界は読み取り画面の「読み取りの調整」で変更可能。登録時も同じ値を使います。
- 登録データはブラウザ内に保存。JSONを書き出せば別端末に移せます。

外形のシルエットを64×64へ正規化して比較します。内部の閉じた模様は塗りつぶして比較するため、内側の飾りをある程度無視できます。ただし暗い装飾が輪郭まで伸びると、外形が欠けて認識される場合があります。穴の違いだけの形は区別できません。命令同士は外形を大きく変えてください。

## 4. 読み取りと実行

1. ブロックを離して一列に並べる。既定は上から下。左から右も選択可能。
2. カメラで撮影、またはJPEG・PNG・WebPの写真を選択。
3. 画面上の番号と命令を確認。自信が低い形は「要確認」となり、命令を選び直すまで実行できません。
4. 動く時間（100〜3000ms）と速さ（PWM 50〜200）を設定し、実行。
5. 「停止」はプログラム全体を終了。停止ブロックより後ろの命令も実行しません。

最大32命令。速度と時間は全命令に共通です。右・左は左右の車輪を逆回転させる、その場旋回です。「90度」「10cm」の制御ではありません。エンコーダなしの時間制御なので機体ごとに調整してください。停止では駆動を止めますが、慣性で少し動くことがあります。

通信中は約350ms間隔で継続信号を送り、Arduinoは約1800ms受信できなければ停止します。別タブへ移った場合もサイトが停止を試みます。ブラウザ終了などで停止送信できない場合はArduino側の通信監視が働きます。PCやネットワークの遅延で途中停止することもあります。

## 現在の範囲

- 白いブロックを木目または暗い背景で撮る試作。軽い傾きを補正します。つながったブロックの分割、重なり、複数列、繰り返し構文には未対応。
- 一致率は形の重なりの指標で、正解確率ではありません。必ず結果を確認して実行。
- 写真はブラウザ内で処理し、画像認識サーバーへ送信しません。フォントの表示にはGoogle Fontsを使用します。
- 実機への書き込み、カメラの実写認識、実機走行は未確認です。付属の検証記録も参照してください。

## 通信仕様（改造用）

全てPOST。ヘッダー `X-Robot-Key` と `Content-Type: text/plain`。

- `/status`：機体名・実行中か・現在の命令番号（0開始）・停止理由
- `/run`：本文 `F,500,120;R,400,120`（命令,時間ms,PWM）。実行中の二重開始は拒否。
- `/heartbeat`：通信監視を更新
- `/stop`：即時に駆動停止

命令はF/B/L/R/S。キーはLAN内HTTPで送る簡易照合用です。インターネットへロボットを直接公開する設計ではありません。

## 認識 v2 の変更

送付された前進・後退・左・右の4つの外形を標準登録しました（写真そのものはサイトに掲載していません）。色味と明るさを組み合わせて白い材料を抽出し、内部の文字を除き、軽い傾きを補正します。外形の左右端を重視して比較します。1命令につき最大5枚の写真を追加できます。旧版の登録は残したまま、新しい保存領域を使用します。旧JSONも読み込めますが、再登録を推奨します。

つないだままでは輪郭が一体になるため、5〜10mm離して撮影してください。白い背景・強い影・大きな回転・輪郭を覆う装飾は認識が難しくなります。自動抽出が合わない場合は「読み取りの調整」で自動を外し、明るさの境界を変更できます。色味による白い材料の選別は手動モードでも有効です。
